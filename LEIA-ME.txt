=====================================================
  BLUESHIELDPRO — SITE INSTITUCIONAL
  Guia rápido de configuração
=====================================================

O site é 100% estático (HTML + CSS + JS). Não precisa de
servidor, banco de dados nem instalação. É só hospedar.

-----------------------------------------------------
1. FORMULÁRIO DE ORÇAMENTO (Web3Forms)
-----------------------------------------------------
O envio usa o Web3Forms (https://web3forms.com) com a chave
de acesso já configurada em orcamento.html:

    <input type="hidden" name="access_key" value="6c39a839-...">

Essa chave está vinculada ao e-mail cadastrado no Web3Forms.
Para trocar o e-mail de destino, acesse web3forms.com, entre
com a conta usada para gerar essa chave (ou gere uma nova
chave lá) e atualize o value do campo access_key nesse arquivo.

O envio acontece via JavaScript (fetch), sem sair da página:
ao confirmar, o botão mostra "Enviando..." e, se der certo,
o formulário é substituído pela mensagem de sucesso. Se falhar
(sem internet, chave inválida etc.), aparece um aviso pedindo
para tentar de novo ou chamar no WhatsApp — nenhum lead trava
sem explicação.

5. IMAGEM DE COMPARTILHAMENTO (og-image.png)
-----------------------------------------------------
As meta tags apontam para og-image.png (imagem exibida ao
compartilhar o link no WhatsApp/redes). Crie uma imagem
1200x630 px com a logo e o slogan e salve na raiz do site
com esse nome.

6. GOOGLE ANALYTICS 4
-----------------------------------------------------
O site carrega UM unico gtag.js e envia para DOIS destinos:

    Google Ads       AW-17972527330
    Google Analytics G-RH3Y7G97J5   (ID do fluxo: 15467399592)

IMPORTANTE: nao cole o snippet pronto que o Google oferece
no painel. Ele traz um segundo <script src=".../gtag/js">,
e dois carregadores na mesma pagina geram dados duplicados.
O padrao correto, ja aplicado aqui, e um carregador so com
uma linha gtag('config', ...) para cada destino.

Para trocar o ID do GA4, edite esta linha no <head> das 13
paginas .html (se ficar vazia, nada e enviado e nenhum erro
e gerado):

    window.BSP_GA4_ID = 'G-RH3Y7G97J5';

Alem dos acessos normais, o site registra no GA4 o evento
"generate_lead" em dois pontos:

  - method: whatsapp             -> clique em qualquer CTA
                                    de WhatsApp
  - method: formulario_orcamento -> envio do formulario

Esses dois eventos continuam disparando a conversao do
Google Ads em paralelo, como antes.

8. IA: llms.txt (como o ChatGPT/Claude/Perplexity
   passam a indicar o site)
-----------------------------------------------------
O arquivo llms.txt na raiz descreve, em texto simples, o
que a empresa faz, para quem atende e quais páginas
existem. É o formato que assistentes de IA leem para
entender e citar um site.

Três peças trabalham juntas:

  - llms.txt          o resumo lido pela IA
  - robots.txt        libera explicitamente os robôs de IA
                      (OAI-SearchBot, ChatGPT-User, GPTBot,
                      Claude-SearchBot, PerplexityBot,
                      Google-Extended e outros)
  - JSON-LD no index  dados estruturados da empresa e do
                      catálogo de serviços

Sempre que mudar serviços, segmentos ou páginas, atualize
o llms.txt junto — ele não é gerado automaticamente.

-----------------------------------------------------
9. RENDER (publicação e headers)
-----------------------------------------------------
O arquivo render.yaml traz headers de cache e segurança.

ATENÇÃO: se o serviço no Render já existe e foi criado à
mão pelo painel, NÃO o converta em Blueprint (o Render
pode criar um serviço novo em vez de atualizar o atual).
Nesse caso copie os headers em:
    Dashboard -> serviço -> Settings -> Headers

Para publicar uma alteração: o Render reconstrói sozinho a
cada push na branch configurada no serviço. Se o push foi
para outra branch, faça o merge nela ou use
    Dashboard -> serviço -> Manual Deploy
